# Market Data v2

## API и MCP

REST использует `GET /api/v2/…` с существующим приватным Bearer-токеном. Схема запросов доступна в OpenAPI коллектора. Данные возвращаются в `data`. Конверт содержит `instrument`, `source`, `exchange_timestamp`, `server_timestamp`, `data_age_seconds`, `is_fresh`, `data_quality_status`, `market_session_status`, `warnings` и `schema_version`. Для снимка каждый блок содержит собственные время и качество. Даты HTTP и MCP передаются в UTC. `UNAVAILABLE` означает отсутствие наблюдений, `INSUFFICIENT_HISTORY` означает недостаток подходящей истории, `PARTIAL_DATA` отмечает неполное покрытие или непроверенную семантику. `MARKET_CLOSED` требует явного расписания. Свежесть и качество — разные поля.

MCP использует существующие OAuth и scope `finam:read`. Каждый новый инструмент принимает один необязательный объект `query`. В таблице приведены значения этого объекта и пути относительно `/api/v2/`. GET-параметры REST передаются без оболочки `query`. Массивы передаются повторением имени параметра. Поля сверх схемы отклоняются. При ошибке приватного API или превышении 1 МиБ MCP возвращает `API_UNAVAILABLE`.

Только REST также предоставляет `market/quote`. Лимит страниц 1–100 строк. Для следующей страницы передайте прежние параметры и `data.next_cursor` как `cursor`. Глубина 5/10/20/50 ограничена фактически наблюдаемыми уровнями. Потоковые интервалы 15/60/300/900/1800/3600 с. История сетки 15 с и минут создаётся вместе с вставкой новых сделок. Ответы потока содержат до 120 последних заполненных UTC-бакетов. CVD считается по всем наблюдаемым бакетам данного окна. `history_window` выражается в секундах. Сырые ценовые профили ограничены 250 000 сделок и 50 отображаемыми основными уровнями. Snapshot возвращает quote, календарь, состояние фидов, свечи, технические индикаторы, стакан, ликвидность, поток, дельту, CVD, OI, профиль, волатильность, аномалии, исследования и межрыночный блок.

## Семантика результатов

- Стакан хранит до 50 ценовых уровней на сторону с биржевой меткой последней обработки строки, если она есть, и локальной меткой наблюдения. Для пустого или пересечённого стакана spread, mid и microprice отсутствуют. При недостаточной глубине дисбаланс соответствующей ширины отсутствует. Изменение объёма и сохранение уровня между двумя снимками отражают наблюдаемую ликвидность. Причина исчезновения объёма неизвестна.
- FINAM_REPORTED_SIDE сохраняет опубликованную сторону сделки. TICK_RULE используется при разных ценах соседних уникальных меток времени в пачке. Неопределённая сторона имеет метод UNKNOWN. Сумма UNKNOWN показана отдельно. Дельта и CVD используют только классифицированный объём и остаются частичными при неизвестном покрытии.
- OI — поле Finam, отдельно для котировки и для сделки. Изменения и перцентиль сравнивают наблюдения одного источника. Времена публикации могут отличаться от наблюдаемого интервала. Интерпретация сочетаний цены и OI описывает гипотезы о поведении рынка.
- Свечные интервалы — 1m, 5m, 15m, 30m, 1h, 4h и 1d. UTC-бакеты могут включать внутрисвечной перерыв. Периоды индикаторов и число свечей указаны в ответе. Сессионные уровни требуют расписания, anchored VWAP начинается с первой свечи окна. Свечной VWAP использует typical price, Volume Profile использует только реальные цены сделок из хранилища.
- Исследования используют конкретный контракт и максимум 10 000 завершённых бакетов. Для исторических условий OI поступает из одного источника, CVD-дивергенция проверяет знак изменения CVD за бакет, а стаканный дисбаланс берётся из наблюдений перед закрытием бакета. Временные ряды микроструктуры по умолчанию копятся с начала сбора. Наблюдения, поступившие после закрытия соответствующего бакета, исключаются. Средние, медианы, квантили и интервалы Уилсона рассчитаны на непересекающихся окнах. Поправка Бонферрони охватывает шесть горизонтов одного запроса. Серийная зависимость и множественные запросы могут исказить интерпретацию. Комиссии, проскальзывание и исполнение требуют отдельного backtest.
- Межрыночные ряды сопоставляются по совпадающим UTC-бакетам без forward-fill, а returns требуют соседних наблюдений. Для сохранённых активного и следующего контрактов Si вычисляется календарный спред. Базис возвращается как `null` до подтверждения спот-источника и коэффициента пересчёта.

## Наблюдения из проверки

В локальную PostgreSQL 16 загружены 320 завершённых минутных свечей `SiZ6@RTSX` из действующего MCP. Это выборки фактических ответов v2. Поле времени в примерах сохранено в формате API (UTC). Последняя свеча соответствовала 03:49 25 ноября по Бангкоку.

```json
{
  "instrument": "SiZ6@RTSX",
  "source": "finam",
  "exchange_timestamp": "2026-11-24T20:49:00+00:00",
  "data_quality_status": "DATA_STALE",
  "schema_version": "2.0",
  "data": {
    "last": 82561.0,
    "provisional": false,
    "price_semantics": "latest stored 1m candle close"
  }
}
```

```json
{
  "instrument": "SiZ6@RTSX",
  "source": null,
  "exchange_timestamp": null,
  "data_quality_status": "UNAVAILABLE",
  "schema_version": "2.0",
  "data": null
}
```

Второй ответ получен для стакана и отдельно для OI в базе, содержащей только реальные свечи. На этой выборке RSI(14) 1m равен 38,5864. Исследование с `rsi_lt_30` нашло 3 окна на горизонте 1 и 2 окна на горизонте 50. Отдельные синтетические тесты проверяют REST, MCP, WebSocket reconnect, агрегацию сделок и отсутствие наблюдений.

## Python-клиент

```python
import os

from marketdata.client import RestMarketDataClient
from marketdata.contracts import SnapshotQuery

async def read_market():
    async with RestMarketDataClient(
        os.environ["COLLECTOR_BASE_URL"],
        os.environ["RESEARCH_API_TOKEN"],
    ) as market:
        return await market.snapshot(
            SnapshotQuery(symbol="SI@CONT", timeframes=["1m", "15m"])
        )
```

Клиент проверяет версию схемы, задаёт таймауты, временно кэширует успешный ответ и ограничивает повторные обращения при отказах. `require_fresh=True` требует свежую котировку и статус HEALTHY у всего снимка. Интеграция с торговым роботом выполняется в `algo_tcs` отдельно.

## Обновление ChatGPT

После staging-проверки и разрешённого обновления MCP проверьте OAuth и вызов `tools/list` по прежнему URL. Должно быть 25 инструментов. В ChatGPT откройте настройки приложений, выберите существующее приложение коллектора и обновите список действий, если эта кнопка доступна. Если ChatGPT продолжает показывать старую схему, переподключите приложение с прежним URL и настройками OAuth из [инструкции MCP](CHATGPT_MCP_SETUP.md). После авторизации в новом чате выполните `get_market_capabilities` и `get_market_snapshot`. Результат discovery в protocol-тесте не подтверждает обновление списка в конкретном аккаунте ChatGPT.

## Готовность компонентов

| Компонент | Что проверено | Что осталось |
| --- | --- | --- |
| Legacy Collector и MCP | Регрессионные тесты и реальное чтение production MCP. При проверке 0 ошибок, ready=true, polling 30 с | Серверные логи за период прежней деградации недоступны |
| Миграция и снапшот v2 | PostgreSQL 16, повторная миграция, восстановление дампа, REST и протокол MCP | Сверить конфигурацию и объёмы на целевом сервере |
| Стакан, сделки и OI | Адаптеры по спецификации, локальные контрактные тесты, имитация разрыва, аналитика на тестовых данных | Финансовые данные новых фидов, snapshot flag, глубина, каденс OI, квоты и права использования |
| Индикаторы и статистика | Вычисления и REST на 320 реальных свечах Si, тест окон и недостаточной истории | Длительный сбор для микроструктурных условий и расширенное исследование с явной моделью исполнения |
| Межрыночный анализ | Сопоставление рядов по UTC, окно корреляции и lead/lag, условный календарный спред | Проверить поставщиков и историю других инструментов, нормировку базы и покрытие сессий |
| Календарь и мониторинг | Праздник, перерыв и отсутствие даты в тестах, footprint PostgreSQL и метрики процесса | Автоматический источник календаря, хостовые алерты и причины прежних ошибок в production |
| API и MCP | 20 REST маршрутов, 19 новых MCP tools и сохранение шести старых. Rate limit, общая схема query и протокольный discovery | Обновление инструментов в ChatGPT на живом подключении |
| Retention и развёртывание | Бюджет, мониторинг размера и план отката. Сбор v2 выключен по умолчанию | Окончательные сроки, партиционирование и политика архивации по измерениям |
| Клиент algo_tcs | Python-интерфейс REST, схема, таймауты, кэш и circuit breaker | Интеграция с роботом потребует отдельного согласования. Потоковый клиент ждёт downstream-стрим API |

В нагрузочном тесте каждая из 10 000 синтетических сделок вставлена в двадцати батчах вместе с двумя гранулярностями агрегатов за 0,51 с. Контрольная агрегация из PostgreSQL заняла 0,011 с, суммарный объём таблиц и индексов около 3,29 МБ. Это замер локальной среды, включая подключение к базе, без сетевой и Finam-нагрузки домашнего сервера. [Оценка диска для Coolify](MARKET_DATA_V2_RUNBOOK.md#бюджет-диска-и-retention).
